# Prototype audit: calls that disagree with their callee

On x86 (Linux and the Windows build) a call is only as good as the declaration the caller compiles
against. The decomp was written for MWCC on the PS2, where several things are harmless that are not here:

- **No prototype.** `f32 sinf();` makes the caller promote a `float` argument to `double`, so the callee
  reads half of a double. Any argument count compiles.
- **Register-class order.** On the EE, integer and floating-point arguments take registers independently:
  the k-th integer argument is `a<k>` and the k-th float is `$f<12+k>`, however they are interleaved
  (checked in the retail asm: `RwMatrixRotate(matrix, axis, angle, combine)` is called with `a2 = combine`
  and `$f12 = angle`). `f(int, float)` and `f(float, int)` are the same call there. On x86 the order is
  the stack order, so a prototype whose order differs from the definition's passes swapped values.
- **64-bit parameters.** One EE register holds an `s64` or an `s32`; on i386 a `long long` takes two stack
  words, so a caller that passes 4 bytes shifts every later argument.
- **Float results.** A function that returns `float` leaves it in `st(0)`. A caller that declared it `void`
  or `int` never pops it, and eight such calls overflow the x87 stack (every float afterwards is NaN).
- **Pass-through registers.** A function that forwards its own `$f12/$f13` to a callee writes nothing before
  the call, so the decomp omitted those arguments; the callee reads stack garbage.

## What runs

`tools/gen_port.py mirror` runs `prototype_unprototyped_declarations` (after the overrides are spliced in):

1. The ABI signature of every function comes from its definition (decomp C, an override or a port source),
   or, with no definition, from its typed prototypes. Types are reduced to the classes that matter:
   integer/pointer word, `float`, `double`, 64-bit integer; a struct by value or an unknown type blocks the
   function.
2. **Typed prototypes that disagree with the definition** are aligned (`align_prototypes_with_definitions`):
   a parameter of the wrong class is retyped; a prototype whose classes are a reordering of the definition's
   is reordered and every call in the unit reorders its arguments to match; a wrong return class (float
   against anything else, or a 64-bit result read as 32-bit words) is retyped. A parameter-count
   disagreement is left alone and listed.
3. **Unprototyped declarations** (`T f();`) of a function with one signature get that prototype, in
   ABI-erased types so no type name has to be visible. Skipped, with the reason listed, when the
   definitions disagree, a parameter is a struct by value, the function is variadic or a call in the tree
   passes another number of arguments (the register forwarders that pass `a0..a3` on).
4. Callees with a definition that the unit never declares (implicitly `int f()`) get a prototype.

`build/prototype_report.txt` lists what was not rewritten and every parameter-count
disagreement. `config/mirror_fixes.txt` retains only audited per-site adapters.
Source-only input/result/type repairs move upstream when the complete retail
match survives; a generic host ABI pass is not itself evidence for a PS2 type.

## Auditing

`sh tools/remote_audit.sh <lane>` (after a warm `remote_check`) runs `tools/audit_prototypes.py`: clang over
every unit with `-Wdeprecated-non-prototype`, `-Wstrict-prototypes`, `-Wimplicit-function-declaration`,
`-Wdouble-promotion` and the pointer-type warnings, summarised by callee. `-Wdouble-promotion` finds float
arguments through an unprototyped call. What remains by design: calls through unprototyped function pointers,
the asm forwarders that pass four registers to a native, calls to functions with no definition in the tree
(asm-only, resolved to a trap or an override with its own signature), and the RenderWare `RwPow/RwSin` macros
that call libm in double on purpose.

`docs/call_arity_mismatches.md` (generated by the audit's `--arity`) lists every remaining call through an
unprototyped declaration whose argument count differs from the definition's: the sites to check against the retail
asm one by one and repair with a `config/mirror_fixes.txt` row.

## Omitted arguments that retail passes through (`config/passthrough_calls.txt`)

On the EE a callee reads `a0..a3` whatever the caller did, so the decomp's `f()` often hides a call where retail
jals with the caller's own incoming register untouched (`kwlnTaskGetWork()` inside a task callback). On x86 the
callee then reads stack garbage. `tools/verify_passthrough.py` reads the retail asm (`mipsel-linux-gnu-objdump -d
-m mips:5900` over `0x100000..0x530000`, as `build/all.s`) and emits a row only when it can prove the repair:

- How many registers the callee takes comes from its asm, not from the call counts: the `a0..a3` it reads before
  writing, plus those it hands untouched to a callee that takes them (a tail `j` counts as a call). That removed the
  false "expected 2" of callees that every caller correctly calls with one argument. Varargs functions (a spill of
  `a1..a3` at entry) are skipped, as are callees with a non-integer parameter at an omitted position.
- The omitted `a<i>` is not written between the function's entry and the jal, and no call comes in between (or its
  last write is an `li` in the same straight-line run, the delay slot included, and the argument becomes that immediate).
- The enclosing function declares an `i`-th integer parameter, or it gains one (`@param` row: `void *p4_a<i>`, the
  definition and every declaration of it follow). A function that gains a parameter is then checked as a callee
  itself: each direct call that omits the argument needs a verified row too, and its caller gains the parameter in turn.
  A chain is kept only when every site in it is verified; otherwise the report says which function was left alone.

`apply_passthrough_calls` in `tools/gen_port.py` applies the rows to the mirror before the task-work pass and the
prototype pass, and fails when the function or the n-th call has moved. A typed declaration of a callee that takes
fewer parameters than a call now passes becomes unprototyped, which the prototype pass then replaces by the
definition's. `config/passthrough_calls_manual.txt` has the same fail-closed
registry contract for evidence established by hand. Both registries now have
zero active rows: their complete audited input chains are expressed upstream,
including the guarded SFADXT reconstructions whose authoritative owners remain
ASM. The registry capability remains available for a genuinely new finding.

Run it with `python tools/verify_passthrough.py --mirror <mirror> --asm all.s --rows out.txt <callee> ...`.
Review proposed chains against their actual callee reads, source ownership and
every caller before accepting them. Historical sweep counts are not acceptance
thresholds for a later source pin.

The second audit's bank chain is now explicit upstream: a 32-bit descriptor,
64-bit flags, a pointer result and an already evaluated unused third key.
`func_00426cf0` is `open(path, flags, mode)`; the fourth GP register a wrapper
forwards is not a fourth open argument. Four-GP SDK forwarding views, true EE
aggregates/128-bit values, variadic interfaces and measured codegen exceptions
remain separately classified in the generated prototype report; they must not
be converted to fixed prototypes by guessing missing values.
