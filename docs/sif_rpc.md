# SIF RPC traffic of the retail game (EE to IOP)

Generated by the PCSX2 trace tooling's sif_summary.py (private, not part of this repository) from `p4hook --sif-cmds`
runs of the retail game in tge's pcsx2-hook. Every EE-to-IOP SIF command goes through `_sceSifSendCmd` (retail
0x00424B78); the table below is what the RPC layer sent, joined from the bind (server id) and call (function id) packets.
"Callers" are decomp functions: the first frame on the logged stack outside the SDK's SIF layer (0x00421000..0x00427000).
Server names are the usual SDK ids; the rest are the game's own IOP modules: 0x80001300..0x8000131f are bound from
`func_0043a978` (code1_0043, unnamed asm in the sound/SDK area), 0x90000200 from `func_004e5738` (src/cri/dtx.c, the CRI
DTX RPC layer). A guessed name is marked with `?`.

The commands below were recorded in two runs. The first is the boot to the title with the opening movie playing (about 7200 frames); the second is the New Game drive to the first
controllable field (30000 frames, opening movie skipped).
