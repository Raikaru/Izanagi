# Limits of the game gates for renderers other than llvmpipe.
#
# The ctest limits in tests/CMakeLists.txt (and the arguments of tests/*.sh) are written for llvmpipe, where the gates are judged in the
# container. On a real GPU the same gates read frames that can differ a little from llvmpipe's. The game reads this
# file (P4PC_GATE_LIMITS, with the gate's name in P4PC_GATE_NAME; src/render/p4gl_gl.c p4gl_gate_limit) and, when the loaded context's
# GL_RENDERER contains the renderer text (any case) of a row for the gate, judges the frame by that row's limit instead.
#
#   <gate (the ctest name)>  <text in GL_RENDERER>  <limit in percent>
#
# A row is the largest value seen in 10 runs of the gate on that GPU plus a margin (above the observed spread, not further).
# Rows may also tighten the ctest's llvmpipe limit on a GPU that reads lower: backend accumulation must not loosen that GPU's gate.
# Measured on the RTX 4080 Laptop (driver 610.88, Windows, GL ES 3.2 through WGL): the initial 20 MAD gates had spread 0.0000
# over ten runs and passed their ctest limits. To calibrate another gate, run it ten times on that GPU with its ctest limit and
# take the largest MAD the runs print, plus a margin.
# Rerun it after a GPU driver update or a renderer change that moves a gate's frame. Gates without a row keep the ctest limit.
#
#gate                         renderer  limit
# systems_minimap              A40       0.73      (example: a GPU that reads 0.671 where llvmpipe reads 0.49; the GL_RENDERER text must name the GPU)
# Ten deterministic native runs: canonical fog 3.6758%, Arcana 2.1008%; renderer_port.md 11.2.
scene_near_fog                 NVIDIA    3.73
scene_near_fog64               NVIDIA    3.73
