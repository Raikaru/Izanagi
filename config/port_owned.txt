# RenderWare extern storage that the port defines (tools/gen_port.py).
#
# The decomp declares each name `extern` and nothing defines it. The port
# defines it as port-owned storage in configure. A name moves to
# config/port_symbols.txt only when retail code is shown to use a fixed address
# for it; its line here then goes. A name the decomp starts to define, or stops
# declaring, fails configure/tables: remove it here.
#
# One C identifier per line. The comment gives the decomp's declaration
# (decomp commit ffb64503, pinned by this repo's decomp/ submodule).
#
# Evidence for the names below (audit when RwEngineInstance moved to retail 0x008872E0):
# - No file in the decomp's src/ or include/ outside src/renderware, src/rw and
#   include/rw uses any of them, so only RenderWare code reads these, and all of it
#   shares the one port definition.
# - tools/retail_symbols.py placed none: only 6 of the 113 functions that touch
#   them byte-match retail in the object set available, and every site in the
#   others is skipped.
# - config/symbol_data_addrs.txt and the retail link map give no address for any.
# Retail RenderWare code may still reference some at a fixed address; that stays
# unproven until a retail site decodes. Re-run the audit before adding a name.
