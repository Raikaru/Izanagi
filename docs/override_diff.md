# Override differential verification

`tools/mipsdiff/ovdiff` runs the retail instructions in an R5900 interpreter and the port's compiled native on the same
guest memory and compares what they return and every byte they write. This page is generated by
`tools/mipsdiff/report.py` from a full sweep; the triage notes come from `tools/mipsdiff/triage.txt`.

## How it works

- **Cases.** For each function (signature from `tools/mipsdiff/sigs.txt`, which `sigs.py` extracts from the override C) the harness
  builds cases from a seed derived from the address and the case number: edge and random integers, floats (0, -0, 1, tiny, huge,
  and in every tenth case NaN/Inf/denormals), and pointers into a 64 KiB scratch arena at 0x01C00000 that is refilled for every
  case with integers, floats and pointers into itself (four fill modes). A word the retail code used as a pointer and found invalid
  is learned as a pointer slot, so structures the function walks become valid in later cases (`-c N` replays the learning).
- **Both sides.** The interpreter (`r5900.c`: 64-bit GPRs and the upper halves, the EE FPU with truncation, no NaN/Inf/denormals and
  clamping, the MMI the game uses, VU0 macro mode) decodes the retail words straight from the loaded image. The native runs through
  a cdecl thunk. Every guest page either side writes is tracked (mprotect plus a fault handler); the pages are restored between the
  runs and compared afterwards, except the interpreter's stack.
- **Engine providers.** The sky driver's VU0 multiplies that retail's FINALIZESTART installs in RenderWare's engine slots
  (`00402390`, `00402410`, `00402470`, `00402510`, `00402570`) are port natives (`src/platform/rw_skytran.c`), installed the
  same way by the GL device, so sweeps, replay and the game call the same functions through the slots and each one is
  compared with its own retail code. Missing recordings and invalid inputs are not counted as successful comparisons.
- **Direct lane users.** Source-checked entries also cover the previously
  unlisted natives `0019b730`, `001ee490`, `003a2ad0`, `003f6440`, and
  `004adb50`. The first three return real 32-bit status values. The sky-state
  setter's second argument remains an ordinary word (state-dependent guest
  addresses are interpreted inside it, not by the call bridge). The model-child
  updater has a void result and one pointer; its override's ANSI declaration
  spells the same types as the former K&R header, without changing its body.
  `mipsdiff_sigs` rejects missing providers and changed result, arity, pointer,
  or FP classes; the existing ordinary-definition/seam matcher is unchanged.
- **Callees.** Where the retail code `jal`s a function that has a native, the interpreter calls that native (VU0 registers are
  copied across), so a comparison covers one function's own code and composes leaf by leaf. A callee with no native is a logged
  stub on both sides: the harness compares the calls (address and the argument registers it reads) and the stub's made-up result.
  The engine allocator slots (0x008873E8..F4) and the libc heap are deterministic and restored with the arena.
  The spline fit (`003b9a40`) preserves retail's exact recurrence allocation requests, including zero;
  `spline`/`spline64` cover zero/one/two-point sizes, signed-half truncation for case 240 (`n = -3`),
  both unconditional seeds, and allocation failure.
  Those standalone caller witnesses do not themselves prove checked-heap-header equivalence.
  Retail `chkmemAllocate(0)` requests 48 raw bytes, returns a 16-byte-aligned payload and
  stores its raw-block backpointer at payload-4. The production RW slots now use those
  matched checked wrappers over literal retail EE newlib, not the former dlmalloc table;
  the [CRT heap oracle](platform/crt_boundary.md#allocator-boundary-and-checked-headers)
  independently compares pointers, complete heap/bin/header bytes and accounting.
  The zero-length recurrence reads the backpointer as a divisor (`k = 0` or `-3`),
  but accumulates no points when `n <= 0`, so its inverse is unused.
- **Verdicts per case.** *exact*: return value and all writes identical. *float tolerance*: floats equal within a few ulps or 2e-5
  (EE truncation against round-to-nearest). *special*: the EE and IEEE disagree by design (a NaN/Inf/denormal read as a float, an
  EE Fmax against an IEEE Inf, a denormal flushed to zero). *mismatch*: anything else. *invalid*: the interpreter faulted (a random
  pointer), hit an instruction it does not model, a call it cannot make, or a native callee crashed; such a case says nothing.
  *inconclusive*: the retail path calls a function that has no native and the native never calls it.
- **Proof of a host-float difference.** When a case is not exact, the retail code is run again with the interpreter doing host float
  arithmetic (round to nearest, IEEE NaN/Inf/denormals, x86 float-to-int, separate multiply and add). If that run matches the native
  bit for bit (or faults at the same address where the native crashed), the difference is float semantics alone and the case counts
  as *proven*; the logic is identical. Differences that stay inside the tolerance without this proof are reported as unproven.
- **Isolation and determinism.** Every function runs in its own forked process from pristine guest RAM, on a private stack, with the
  main stack read-only (a wild write by a native faults instead of corrupting the harness). Natives run on a zeroed private stack, ASLR
  is switched off by re-exec when the host allows it, the only host pointers the interpreter will call are the port's natives and the
  harness's own callbacks, and random integers avoid the harness's own address ranges. Runs are reproducible (the subset was run 32
  times under load with `-fstack-protector-strong` with identical rows). memcpy/memset are logged on both sides (`--wrap`).

`-F` runs the retail code on its own the whole way (callees that have a native are interpreted too: the soft-float double helpers and libm cores run as retail's code, the native
keeps its host doubles), `-Q` compares the retail double libm cores and `ADX_GetCoefficient` with the port's bindings and constants (docs/porting.md, "The libm cores are the
retail code"); `domains.txt` limits an argument to the values the game passes.

Run: `ovdiff -n 40 -o out.tsv <SLUS_217.82> all` (or addresses, `@file`); `-c N -v` replays one case and prints the verdicts,
`P4_TRACE=1` adds the interpreter's instruction trace. ctest `ovdiff_subset` runs `tests/ovdiff_subset.txt` on every check.

## Host differences (accepted)

- **EE float arithmetic**: the port runs game code with MXCSR round-toward-zero, flush-to-zero and denormals-are-zero, add/sub through the EE adder
  (aligned with one guard bit, then truncated) and div/sqrt rounded to nearest (see "EE float mode" in `docs/porting.md`: the decomp mirror is compiled through
  `tools/ee_float_cc.py`), and the interpreter models the same, so those operations match bit for bit; the natives in this harness run in the same mode.
  What stays different: the EE clamps to +-Fmax and has no Inf/NaN (MXCSR gives the flush, not the clamp; measured on the golden replay: 24 clamped results,
  no saturating conversion), and port natives that do not go through the rewrite and the double libm bindings (`acos`, `log10`, `pow`). The
  "proven" verdict's host-float rerun runs the same EE add/sub/div/sqrt and MXCSR mode, so it explains float to int saturation and NaN differences only.
- **NaN, Inf, denormals**: the EE has none (exponent 255 is a large number, results clamp to +-Fmax, denormals flush to zero); the
  host produces NaN/Inf and keeps denormals. Float-to-int conversion of an out-of-range value saturates on the EE, gives INT_MIN on x86.
- **Sign of zero**: the host can give -0 where the EE gives +0.
- **libm against retail polynomials**: sin/cos/acos/atan agree to about 1e-5 relative.
- **Aligned VU0 loads**: retail `lqc2`/`sqc2` mask the low 4 address bits; the native helpers use aligned SSE accesses, so an
  unaligned operand crashes the native (real callers pass 16-byte aligned data).
